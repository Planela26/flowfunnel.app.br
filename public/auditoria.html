🔐 9. Segurança ✅ Aprovado (após correções)

  • Multi-tenant: isolamento verificado em todos os endpoints — userId sempre da sessão, nunca do cliente
  • Endpoints públicos de pixel: não criam receita nem atribuição — só eventos rastreados e promoções de webhooks autenticados
  • SQL Injection: Prisma ORM com parametrização automática — sem raw SQL nos arquivos novos
  • XSS: JourneyExplorer usa valores em JSX (React escapa automaticamente) — sem dangerouslySetInnerHTML
  • CSRF: endpoints de escrita usam session-based auth (NextAuth cookie httpOnly)
  • HMAC de webhooks: todos os 5 handlers validados com segredos via guardWebhook
  • PII nos logs: apenas platform + transactionId — sem email/telefone exposto
  • Respostas de erro: retornam apenas { error: string } — sem stack trace

⚠️ Limitações de APIs de Terceiros (sem solução técnica)

  • WhatsApp → lead_id: A Meta não expõe o clique de anúncio na conversa — impossível vincular deterministicamente sem extensão manual na landing page
  • Compra em dispositivo diferente: lead_id do localStorage não existe no segundo dispositivo → cai para probabilístico por email/telefone
  • iOS/Safari ITP: localStorage pode ser limpo após 7 dias de inatividade — visitor_id sobrevive, lead_id pode ser perdido
  • Stripe marketing attribution: webhook do Stripe é exclusivo para billing interno — atribuição de marketing fica nas plataformas de checkout

💡 Melhorias Recomendadas para o Futuro

  • Validação Zod nos endpoints públicos de track — tipagem de runtime para payloads malformados
  • Alerta de demo-mode no dashboard quando OPENAI_API_KEY ausente
  • Streaming SSE nas sugestões da Flow.ai — feedback progressivo em vez de esperar 5s
  • Cache de atribuição probabilística — busca por email/telefone custosa; cache de 5min reduziria carga
  • Índice requestId em WebhookLog — campo sem índice há 2 auditorias
